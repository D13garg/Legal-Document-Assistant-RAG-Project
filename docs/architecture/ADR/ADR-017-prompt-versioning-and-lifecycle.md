# ADR-017: Prompt versioning and lifecycle

## Status
Accepted

## Context
The frozen DAG gives `prompts` no dependency (`depends_on = []`); `grounded_generation`, `answering` and `evaluation` may depend on it. Step 9 built the egress chokepoint (ADR-006): `GenerateText` accepts `instructions` plus `ContextSegment`s that each carry a mandatory `ProofResource` source, verifies a proof through the shared `ProofVerifier`, and enforces size limits (500 segments, 50 000 characters per segment, 400 000 characters for instructions plus context together, 20 000 characters of instructions). The handoff said prompt construction must accept only `AuthorizedContext`; that type is not defined anywhere (ADR-006 decision 2 deliberately left it out of the gateway) and creating it would mean changing frozen Step 3. ADR-022 (untrusted-content handling) is deferred by owner decision.

## Problem
Provide one place that turns trusted template text, an untrusted user question and ordered untrusted document text into the instructions and context the gateway will send, such that the result is deterministic, keeps per-resource provenance, never silently alters or drops legal text, cannot be mistaken for an authorization, leaks nothing, and fits the gateway's actual limits. This is Step 10 only; it is not the answer-generation pipeline.

## Decision
1. **Purpose and scope.** `prompts` owns prompt rendering and the lifecycle of immutable, code-defined, versioned templates. It is a pure module: `depends_on = []`, `owns_schema = ""`, layers `domain` and `application` (no `infrastructure`: there is nothing to adapt), plus `api`, `testing`, `tests`. Public API: `PromptRenderer`, `PromptRequest`, `PromptContextInput`, `RenderedPrompt`, `RenderedContextPart`, `PromptLimits`, `PromptCatalog`, `PromptTemplate`, `production_catalog()` and the four error codes (`api.lock`).
2. **Templates are code.** A template is an immutable `PromptTemplate(template_id, version, instructions, test_only)` defined in source under `domain/catalog/`. `template_id` matches `[a-z][a-z0-9_]{0,63}`; `version` is a positive integer; trusted instruction text must not contain a structural marker. A `PromptCatalog` is a tuple keyed by `(template_id, version)`; lookup is exact (types included: `True` is not version 1) and an unknown pair fails with `prompt_template_unknown` without echoing the input. A new wording is a new version; an existing version is never edited in place once approved.
3. **No database, persistence, activation state or cache.** No schema, migration, tenant-specific template, runtime editing, filesystem lookup or cache exists. Selection is explicit in the request; there is no "active version" and no implicit default. Evaluation-gated activation is governed by ADR-030 and a later invariant and is not implemented here.
4. **Authorization-agnostic rendering; the composition boundary.** `prompts` imports neither `access_control` nor `ai_gateway` nor `bootstrap`. It accepts its own neutral input and may use the neutral `ProofResource` from `shared/ports` as provenance. It never creates `AuthorizedContext`, `AccessScope`, `AuthorizationProof`, `AuthorizationDecision` or `ContextSegment` (AG090 is unchanged and grants `prompts` nothing). A `ProofResource` in a prompt request states where text came from; it is not proof that anyone may see it. **The handoff rule "prompt construction accepts only `AuthorizedContext`" is satisfied at the future composition boundary:** the later `grounded_generation` layer converts an authorized context into the neutral `PromptRequest` and maps `RenderedPrompt` into `GenerateTextCommand`. This is a deliberate interpretation. The real egress gate remains the gateway's injected `ProofVerifier`; rendering is never evidence of authorization.
5. **`RenderedPrompt`.** An immutable value: `template_id`, `template_version`, `instructions: Sensitive[str]` and `context: tuple[RenderedContextPart, ...]`, where each part keeps its own `ProofResource` and a `Sensitive[str]` text. One input part gives exactly one output part in the caller's order; resources are never merged or flattened into one string. No gateway DTO is returned or imported. Nothing else is exposed (no digest, hash or telemetry field).
6. **The question lives in the instructions.** The user question is rendered into the instructions as a labeled, delimited, escaped block after the template text. The gateway API is unchanged (no `user_input`) and the question gets no synthetic resource or segment. It is untrusted input, not a trusted instruction.
7. **Trust labels, delimiters, escaping.** Every structural line starts with the fixed marker `[[LDA:`. Blocks are `[[LDA:BEGIN block=<name>[ part=i/n] trust=untrusted]]`, the text, `[[LDA:END block=<name>[ part=i/n]]]`, joined by `\n`. Context part `i` of `n` carries its position, so a part cannot be moved or dropped without the text changing. Untrusted text is escaped by one rule: every occurrence of the marker (matched case-insensitively, original case kept) is preceded by an odd number of backslashes; `k` backslashes already before it become `2k + 1`. The rule is deterministic (no nonce, clock or randomness) and reversible (`unescape_untrusted` is its exact inverse, covered by round-trip and randomized tests). Nothing else is changed: no Unicode normalization, trimming, truncation, reordering or removal. Because escaping and wrapping change the text handed to the gateway, **the gateway's request SHA-256 differs from a hash of the raw question and document text**; anything that compares them must hash what was actually sent.
8. **Trust-boundary statement (narrow).** Document text and user questions are untrusted data. The labels, delimiters and escaping are defense in depth for the text layout only: they stop a question or document from trivially closing a block or forging a structural line, and nothing more. They are not a complete prompt-injection solution, and this module does not claim prevention or immunity. How a model treats instructions inside untrusted blocks, and any provider-specific separation of instructions from context, are not proven by this module (no real provider adapter exists). Only the exact marker (in any letter case) is neutralized; look-alikes such as other bracket styles, homoglyphs or whitespace variants are not. The broader untrusted-content policy and controls of ADR-022 remain deferred.
9. **Validation, limits, determinism.** Validation fails closed before a result exists: the request and every item must be the exact types; text must be `Sensitive[str]` holding exactly `str` (no subclass); NUL and lone surrogates (text that cannot be encoded as UTF-8) are malformed; a blank question or blank context text is invalid; an empty context tuple is `prompt_context_empty`; a context that is not a tuple is invalid (as in the gateway); resource kind matches `[a-z][a-z0-9_]{0,63}` and id is 1 to 256 printable characters (the same as the gateway). Other control characters are legal text and pass through. Each `Sensitive` is read exactly once. Nothing is truncated, dropped, merged, sorted or reordered. **Character counting** is `len(str)`: Unicode code points, no normalization (a combining mark counts, an astral character counts once), identical to the gateway. All limits apply to the **rendered** text (wrapper and escaping included), so an accepted prompt always fits; raw length is a lower bound, so an oversized raw input is rejected before escaping. Slice `prompts` (`LDA_PROMPTS__*`): `max_parts` 500, `max_part_characters` 50 000, `max_instruction_characters` 20 000 (template text, wrapper and escaped question), `max_question_characters` 8 000 (raw), `max_total_characters` 400 000 (rendered instructions plus all rendered parts, the same sum the gateway checks). The slice is checked against the gateway's limits in `bootstrap/prompts.py` (`build_rendering`); any prompts limit above the matching gateway limit is `ConfigurationError("prompts_limits_exceed_gateway")` and the container is not built. Two frozen contracts shape that file: only `bootstrap/ai_gateway.py` may import the gateway (Step 9), so the gateway's four limits arrive as plain integers (`GatewayBounds`) read by the composition layer from its own gateway settings; and bootstrap names may not contain domain vocabulary such as "prompt" (Step 1), so the functions are `load_rendering_settings`, `build_rendering`, `rendering_limits` and the class `RenderingContainer`. The gateway remains the final egress guard and its validation is not duplicated. Rendering is a pure function of `(catalog, limits, request)`: identical input gives byte-identical output and metadata; no randomness, clock, environment, hidden filesystem access, implicit sorting, mutable global state or cache. The wrapper reduces the text capacity of a part (106 to 114 characters per part for up to 500 parts, plus any escaping), so callers must size chunks with margin; chunking's default 2 000 characters leaves a wide one.
10. **Errors.** All failures are `ValidationError` with stable codes: `prompt_invalid_input`, `prompt_limit_exceeded`, `prompt_context_empty`, `prompt_template_unknown`. The message is the code. `detail` is a constant such as a field name (`question`, `context_text`, `resource`) or a limit name (`max_part_characters`), never content, an identifier from the request or a tenant value. No library exception text is surfaced; the only caught exception is the typed `UnicodeEncodeError` of the UTF-8 check, raised without chaining. Misconfigured templates and limits (developer errors) are `ValueError` at construction.
11. **Privacy.** All prompt text is `Sensitive`. The module has no logging, printing, audit emission, persistence, telemetry, digest or cache (ADR-020, ADR-032). Only `template_id` and `template_version` are exposed as metadata. A future source-template fingerprint may be considered separately; it is not part of Step 10.
12. **Test-only template.** The framework ships one template, `test_only_question_context` v1 (`test_only=True`), whose wording is a neutral statement about untrusted blocks. It is **not** an approved production template. `PRODUCTION_TEMPLATES` is an empty tuple; `production_catalog()` returns an empty production catalog, and a production catalog refuses a `test_only` template at construction. The test template is reachable only through `prompts.testing` (importable from tests and `testing/` only, AG010). No production legal-answer wording, disclaimer, citation rule or legal reasoning instruction exists, and none is invented here; there are no templates for summarization, clause analysis, comparison or conversation history. Until a production template is approved, the bootstrap container's renderer answers every request with `prompt_template_unknown`.
13. **Downstream composition.** Step 11 onward composes: `grounded_generation` turns an authorized context into `PromptRequest`, renders, builds `ContextSegment`s (permitted there by AG090) from the rendered parts with their provenance, and calls `GenerateText` with a proof for exactly those resources. One platform test (`tests/platform/test_prompts_composition.py`) shows the mapping with `ai_gateway.testing.build_segment`, the fake provider and the fake verifier, and that an unauthorized request still reaches no provider. It adds no production dependency between the modules. Provider-side separation of the instruction channel from the context channel is **not** proven: only a fake provider exists.
14. **Deferred and known risks.** Deferred: production templates and their review; evaluation-gated activation (ADR-030); retrieval, citations, `GenerationRecord`, answer-schema validation and `INSUFFICIENT_EVIDENCE` handling; conversation history; the broader ADR-022 policy; content scanning; a source-template fingerprint. Risks: delimiters and escaping are not a security guarantee (decision 8); no real content scanner and no real provider adapter exist; the historical Step 6 `api.lock` baseline remains unverified; the Step 9 architecture detector is a static control-flow guard with known limits; the Step 10 detectors are likewise static AST checks.

## Rationale
A pure function with explicit versions is the smallest design that is deterministic, testable without infrastructure and impossible to turn into an authorization bypass: it cannot ask who the caller is, cannot reach the provider and cannot build the segments the gateway accepts. Escaping the single marker, rather than every bracket or backslash, preserves legal text almost verbatim while keeping the layout unambiguous, and the odd-backslash rule is reversible. Checking limits on rendered output makes "fits the gateway" a property of the renderer rather than an estimate of expansion (escaping can nearly double a worst-case input).

## Alternatives considered
- A `RenderPrompt` use case: needs an audit marker or a new exemption for a function with no effects; rejected (Step 10 does not touch the audit exemption pin).
- Taking `AuthorizedContext` in `prompts`: the type does not exist and would change frozen Step 3 and the DAG, or make `prompts` depend on `access_control`.
- Returning `GenerateTextCommand` or `ContextSegment`: would import `ai_gateway` (a DAG violation) and violate AG090.
- Random nonce delimiters: non-deterministic output, which breaks byte-for-byte repeatability.
- Escaping every `[`, `\` or `<`: changes far more legal text and gains nothing against the one structural marker.
- Raw-length limits with a worst-case expansion factor: would force limits at half the gateway's to be safe.
- A database-backed catalog: persistence, migrations and an activation workflow that belong to the evaluation step.
- A prompt digest in the result: content-derived and guessable for short prompts; ADR-006 already keeps the gateway's digest out of logs.

## Consequences
- Prompt wrapper and escaping add characters, so the gateway's request hash covers the escaped text (decision 7) and each part has a little less capacity than the gateway segment limit.
- Until a production template is approved, nothing outside tests can render a prompt.
- `grounded_generation` must size its parts with margin and must construct `ContextSegment`s itself.
- Whitespace-only context text is rejected rather than forwarded, which the gateway alone would have accepted.

## Security implications
Prompt text, questions and context never appear in errors, `repr`, logs or telemetry (`Sensitive` everywhere; none emitted). The renderer cannot grant, mint or check access and cannot reach a provider. Injection defense is limited as stated in decision 8. A production template added later is trusted text and is the highest-value change to review (CODEOWNERS `domain/catalog/`, owner `ai-quality`). `tests/architecture/test_prompts_boundaries.py` pins the imports, the absence of authorization types and segments, statelessness, determinism, the empty production catalog, content-free errors and the unchanged AG090.

## Operational implications
Optional `LDA_PROMPTS__*` variables tune the limits; all have safe defaults and must not exceed the gateway's (checked at composition). No new secrets, dependencies, schema or queue.

## Migration implications
None (no schema). Adding a template is a code change that adds a version; moving to a persisted or activated catalog later needs its own ADR and migration.

## Amendment (Step 14, 2026-10-16): the first production template
Decisions 12 and 14 above describe the Step 10 state (an empty `PRODUCTION_TEMPLATES`) and are superseded by this amendment as of 2026-10-16. `PRODUCTION_TEMPLATES` now holds exactly one template, `grounded_answer` v1, approved by the project owner for the exact instruction text with SHA-256 `2e3a3ce3b2b0a36bf212a4ed7ec3d07ec2f4ebee4f3882694071e48cd64cb94a` (ADR-029 D8; the approval is the project owner's only, not a team's). `production_catalog()` returns a production catalog containing only that template; any other `(template_id, version)` fails closed with `prompt_template_unknown`; a production catalog still refuses any `test_only` template at construction, and the test-only template stays reachable only through `prompts.testing`. The frozen rules are unchanged: no database, no activation state, no runtime editing, selection by explicit id and version, a new wording is a new version. No error code, public API entry or API-lock line changed.
