# ADR-037: Document processing: original access, extracted artifact, parsers and limits

## Status
Accepted

## Context
ADR-010 §13 and ADR-005 §6 left two questions to Step 7: how a pipeline stage obtains the original bytes (the key layout is Documents', ingestion imports no module) and what the first real stage produces. The DAG already allows `document_processing -> {documents, ingestion}`. Chunking (Step 8) needs the extracted text and structure; ADR-032 forbids content caches; ADR-005 keeps content out of Postgres; ADR-023 says every module that holds derived data hooks `DocumentPurged` and keeps its own receipt. The owner approved the three decisions below before implementation.

## Problem
Define a read path for originals that keeps the key layout private and cannot be misused as a general content API; define the derived artifact, its immutability and crash-safe idempotency; define parsers, limits and the permanent/retryable split; and define how the derived data is purged, without new infrastructure, new module edges or changes to frozen ingestion contracts.

## Decision
1. **Original access (Documents, additive).** `documents.api` gains `ReadOriginal(ctx: SystemContext, document, version) -> OriginalContent` (`@public`, `@not_audited`). It opens a tenant-bound read transaction (RLS), requires the document to be `active`, the version to belong to it and to be `pending`, closes the transaction, and only then reads the object through Documents' own `ObjectStore` and key layout. A tombstoned document, a foreign version or a version that left `pending` is refused; a stored size different from the recorded size is refused (`document_original_size_mismatch`). The body never appears in a repr (`field(repr=False)`), an event, a log or an audit fact. Ingestion is untouched and does not import Documents.
2. **One stage, `extract`.** `document_processing.api.ExtractStage` implements `PipelineStage` (name `extract`). The mandatory `scan` stage stays first and is not bypassed; Step 7 adds no scanner (ADR-036 stays as is), so no document reaches `ready` end to end until a real `ContentScanner` is supplied at composition.
3. **Derived artifact.** One immutable object per version at `document_processing/<doc>/<version>/extracted` (relative to the tenant prefix), written with `overwrite=False`: canonical JSON (sorted keys, ASCII, no whitespace) holding `schema`, `media_type`, `page_count` and the ordered `blocks` (`heading` with level 1-9, `paragraph`, `list_item`; PDF blocks carry their page). Text is Unicode NFC with control, format, surrogate and unassigned code points removed, spaces collapsed and layout line breaks joined; the same input always gives the same bytes. Only identifiers, the SHA-256, the parser version and counts are stored in Postgres (`document_processing.extractions`); extracted text never enters Postgres, an event or a log.
4. **Crash-safe idempotency, row first.** Per run: read original -> extract -> ONE fenced transaction (`fence.verify`, then insert-if-absent of the extraction record) -> write the object. A row without its object is the only intermediate state; it is findable by the purge, and running the stage again completes it. Re-running with a recorded row: same parser version and same hash -> the object is written if absent or verified if present (`ADOPT`); a different parser version -> the recorded output is kept and its object must still exist and match the recorded hash (`KEEP_RECORDED`); the same parser version with a different hash -> permanent failure `artifact_conflict`. An existing object whose hash differs from the recorded one is never overwritten (`artifact_conflict`); a recorded artifact that has vanished and cannot be rebuilt is `artifact_unrecoverable`. The parser version is `extract-1; pypdf=<version>; defusedxml=<version>`.
5. **Parsers (infrastructure only).** PDF: `pypdf`, text layer only; encrypted PDFs (including owner-password-only) are refused because decryption needs a dependency the project does not have. DOCX: `zipfile` plus `defusedxml` (`forbid_dtd`), main document part only, duplicate entries refused, declared and actual decompressed size capped, paragraphs read iteratively, headings from `Heading1-9`/`Title` styles, list items from `numPr`, tables as their cell paragraphs, `mc:Fallback` branches skipped. Plain text: UTF-8 (BOM allowed) or UTF-16 with a BOM; no other encoding is guessed; NUL bytes are refused. The parser is chosen by the media type Documents recorded, never by sniffing. No OCR, no external service, no subprocess.
6. **Limits (slice `document_processing`, ADR-031).** `max_bytes` (default 50 MiB), `max_pages` (1000), `max_characters` (10 000 000), `max_expanded_bytes` (64 MiB, DOCX part decompression). Page and size limits are decided before extraction; the character limit aborts while accumulating.
7. **Failure classification.** Permanent (`StagePermanentFailure`, never retried, the version becomes `failed`): `unsupported_media_type`, `malformed_document`, `encrypted_document`, `empty_document`, `no_extractable_text`, `limit_exceeded.{bytes,expanded_bytes,pages,characters}`, `version_unavailable` (not pending, tombstoned or foreign), `original_missing`, `artifact_conflict`, `artifact_unrecoverable`. Everything else (storage or database errors, an unexpected exception, a lost fence) propagates and is retried by the engine under ADR-010 §8.
8. **Purge.** `PurgeExtractions` is the handler of Documents' `DocumentPurged` (`ASYNC_JOB`, retried and dead-lettered by the platform): it lists its own rows for the document, deletes each artifact, verifies absence, then removes the rows and inserts an insert-only receipt (`scope = document_processing.extracted_artifacts_and_rows`, version ids) in one transaction. A changed version set aborts and retries. Idempotent: a document that already has a receipt is left alone. The receipt claims nothing about originals, chunks, indexes or backups. `DocumentDeleted` needs no action: this module has no read path in Step 7, and the future reader must consult Documents (as `ReadOriginal` does) before serving.
9. **Persistence.** Schema `document_processing`, migration `e0001`: forced RLS on both tables, no cross-schema reference, no `UPDATE` grant plus a trigger that rejects updates for every role, `DELETE` only on extractions (purge), receipts insert-only with `TRUNCATE` blocked, CHECKs on hash, parser version and counts.
10. **Wiring.** `bootstrap/processing.py` builds the stage; `bootstrap/documents.build_original_reader` builds the reader before `build_ingestion` (ingestion needs the stage and Documents needs ingestion). `documents.api` exports the use case; `document_processing.depends_on = ["documents", "ingestion"]`.

## Rationale
A small, additive read use case in the owner of the key layout is the smallest way to let a later module read originals without ingestion or the layout leaking, and its checks make it unusable as a general read path. A row-first record gives deterministic findability without an intent table or a bucket listing, because the artifact is a pure function of the original and the parser version. Recording and comparing the hash makes "never overwrite conflicting immutable output" a checked rule rather than a convention.

## Alternatives considered
- `document_processing` computing the original's key: leaks the layout and breaks ADR-005 ownership.
- Object first, row second: a crash leaves an object the purge cannot find (the `DocumentPurged` event carries only a count).
- Persisting nothing and re-parsing in chunking: smaller, but parses twice and makes `extract` a validation gate only.
- Overwriting the artifact when the parser version changes: violates immutability and changes what chunking already consumed.
- Decrypting owner-password PDFs: needs `cryptography`/`pycryptodome`; deferred.
- OCR, an external extraction service or subprocess isolation: out of scope by owner decision.

## Consequences
One more module, one more schema, two runtime dependencies (`pypdf`, `defusedxml`). A re-run after a parser upgrade keeps the older output. A DOCX table loses its grid; a PDF page usually becomes one or a few paragraphs, because pypdf does not expose paragraph structure. Page-less formats have no page attribution. Known limitations: in-process PDF parsing cannot guarantee a hard CPU or memory bound against a hostile file (the limits are checks, not isolation); a stale worker's artifact write that lands after a purge can leave an unreferenced object (the same bounded class as ADR-005 §7; the fence protects database writes only); an orphan object created that way is not found by any purge; a recorded row whose object vanished after a parser change fails the version as `artifact_unrecoverable`.

## Security implications
Tenant comes only from the job row and the tenant-bound transactions; every statement carries the tenant predicate and RLS enforces it again. `ReadOriginal` refuses anything that is not a pending version of an active document of the caller's tenant. Untrusted content is parsed with hardened XML (no DTDs or entities), capped decompression and a capped page and character budget. Failure codes, logs and events carry identifiers and codes only. No failure can move a version to `ready`: only `IngestionCompleted` does (ADR-010 §6), and every `extract` failure is either a permanent failure or a retry.

## Operational implications
Configure the `events` queue (purge handler) next to `documents` and `ingestion`; optionally the `document_processing` slice. Dead-lettered `event:document_processing.purge_extractions` jobs mean derived data of a purged document remains. The `ingestion` watchdog delay must exceed the longest extraction (a large PDF can take minutes). Large documents are held in memory while parsed (bounded by `max_bytes`).

## Migration implications
`e0001` creates the schema (branch `document_processing`). Add `PROCESSING_MIGRATIONS` to the migration locations. `pyproject.toml` gains `pypdf` and `defusedxml`. `documents.api.lock` and `document_processing.api.lock` change (additive).
